Two fixes in WebSidebar.tsx:

**Fix 1 — Scan and Collections navigation broken (UAT gap 3):**
The debug diagnosis states router.push calls silently fail for non-existent or incorrectly-resolved routes. However, the routes DO exist:
- `app/scan/index.tsx` is registered in root layout as `name="scan"` with `presentation: "modal"`
- `app/(tabs)/collections/index.tsx` exists within the tabs group

The issue is likely that `router.push("/scan")` works on mobile (where the Pressable is inside the MobileTabBar rendered from within the Tabs navigator) but may behave differently on web. The more explicit path is needed.

For the Scan SidebarItem:
- Change `router.push("/scan")` to `router.push("/scan" as any)`
- If this still fails silently at runtime, the fallback is `router.navigate("/scan")` — but try push first since it works in MobileTabBar

For the Collections SidebarItem:
- Change `router.push("/collections" as any)` to `router.push("/(tabs)/collections" as any)`
- The `(tabs)` prefix may be needed when navigating from within a component that's rendered as part of the Tabs layout, since expo-router needs the full group path to resolve nested routes

IMPORTANT: If at runtime both items still don't navigate, the executor should check the browser console for errors and try alternative approaches:
1. `router.navigate()` instead of `router.push()`
2. Using `href` prop with `Link` component instead of imperative navigation
3. Using `Linking.openURL()` as last resort for web

**Fix 2 — Width consistency:**
Non-TabTrigger items (Collections, Scan) may render narrower than TabTrigger-wrapped items due to the Slot wrapper adding implicit layout behavior.

- Add `alignSelf: "stretch"` to the SidebarItem component for both plain items (Collections and Scan) by passing it as a style override. However, SidebarItem already has `width: "100%"` which should handle this.
- The real fix: wrap the non-TabTrigger SidebarItem calls in a View with `style={{ alignSelf: "stretch" }}` to ensure they stretch the same as the Slot-wrapped items. Actually, since SidebarItem already has `width: "100%"`, the width issue is likely from the parent flex context. The nav items container View uses `gap: 4` and its children are either TabTrigger (which adds its own wrapper behavior) or plain SidebarItem. Test at runtime — if width is still inconsistent after fixing the routing, the fix is to ensure the parent View has `alignItems: "stretch"` (which is the default for flexDirection: "column", so this should already work).

Minimal change: just add `alignItems: "stretch"` explicitly to the nav items container View (`<View style={{ gap: 4 }}>` becomes `<View style={{ gap: 4, alignItems: "stretch" }}>`) to guarantee all children stretch to full width regardless of wrapper differences.
