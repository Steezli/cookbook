Two fixes in WebSidebar.tsx:

**Fix 1 — Scan and Collections navigation (UAT gap 3):**

Both `router.push("/scan")` and `router.push("/collections" as any)` silently fail on web. The routes exist — `app/scan/index.tsx` is a root Stack.Screen modal, `app/(tabs)/collections/index.tsx` is a nested route in the tabs group. The identical `router.push("/scan")` call works in MobileTabBar on native (UAT test 3 passed). The difference is platform: the sidebar only renders on web.

Root cause: `router.push()` on expo-router web (v6 / Expo SDK 54) pushes a new entry onto the web history stack, but when called from within a nested Tabs navigator context, it can fail to resolve routes that live outside the current navigator (scan) or that are non-tab routes within the same navigator (collections). `router.navigate()` resolves routes from the root navigator on all platforms and is the correct API for cross-navigator and non-tab navigation.

Apply these exact changes:

Line 68 — Collections onPress: change `router.push("/collections" as any)` to `router.navigate("/collections" as any)`. The `as any` cast is needed because `/collections` is not a typed tab route (it's a nested non-tab route within the (tabs) group). Do NOT use `/(tabs)/collections` — Expo Router strips group prefixes from URLs, so `/collections` is the correct URL path.

Line 75 — Scan onPress: change `router.push("/scan")` to `router.navigate("/scan")`. No `as any` cast needed — `/scan` is a typed root route. Do NOT use `router.push` — `navigate` is required for reliable cross-navigator resolution on web.

**Fix 2 — Width consistency:**

Add `alignItems: "stretch"` to the nav items container View. Currently the container is `<View style={{ gap: 4 }}>`. Change to `<View style={{ gap: 4, alignItems: "stretch" }}>`. This guarantees all children (both TabTrigger-wrapped SidebarItems and plain SidebarItems) stretch to the full container width, regardless of any implicit layout differences the TabTrigger Slot wrapper introduces. No other width changes needed — SidebarItem already has `width: "100%"` on its Pressable.
