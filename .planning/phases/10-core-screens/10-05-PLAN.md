  <action>
Create `app/(tabs)/recipes/[id]/cook.tsx` -- a new Expo Router route for the cooking mode walkthrough.

**Route setup:**
```typescript
import { router, useLocalSearchParams } from 'expo-router';
const { id } = useLocalSearchParams<{ id: string }>();
```

**Data loading:**
- Load recipe via `getRecipeById(id)` in useEffect
- Store in state. Show ActivityIndicator while loading.
- If recipe has no steps, show "This recipe has no steps" message with a back button.

**State:**
- `currentStep: number` (0-indexed) -- tracks which step is displayed
- `recipe: Recipe | null` -- loaded recipe data

**Overall layout (no nav chrome -- focused experience):**
```
<View style={{ flex: 1, backgroundColor: bgPage }}>
  {/* Top bar: X button + progress bar */}
  <TopBar />
  {/* Content area */}
  <ContentArea />
  {/* Bottom nav: Previous / Next */}
  <BottomNav />
</View>
```

**Top Bar:**
- flexDirection: 'row', alignItems: 'center', padding: 16
- Left: X button (lucide X icon, size 24, textPrimary). onPress: `router.back()`. Goes back to recipe detail.
- Center: Recipe title (fontFamilyDisplay, fontSizeBase, textPrimary, numberOfLines: 1, flex: 1, textAlign: 'center')
- Right: Step counter text "Step {currentStep + 1} of {recipe.steps.length}" (fontSizeSm, textSecondary)

**Progress Bar (below top bar):**
- Container: height 4, backgroundColor borderDefault, borderRadius 2, marginHorizontal 16
- Fill: height 4, backgroundColor accentBlue, borderRadius 2
- Width as percentage: `width: \`${((currentStep + 1) / recipe.steps.length) * 100}%\` as any`
- This follows the research recommendation of percentage-based fill (no Dimensions.get needed).

**Content Area (breakpoint-responsive):**

**Mobile/Tablet layout:**
- Centered vertical stack. Padding: 24 mobile, 32 tablet.
- Step number badge: 48px circle, accentBlue background, white text (fontSize2xl, fontFamilyDisplay), centered.
- Step instruction text: fontSizeXl, fontFamilyBody, textPrimary, lineHeight ~28, marginTop 24, textAlign center on mobile.
- "You'll need" card: bgCard background, radiusMd, padding 16, marginTop 32.
  - Card header: "Full Ingredient List" (fontSizeSm, fontFamilyBodyMedium, textSecondary, marginBottom 12)
  - List all recipe ingredients (recipe.ingredients), each as a row with a bullet point and ingredient text (fontSizeBase, fontFamilyBody, textPrimary)
  - Per user's discretion decision in CONTEXT.md and RESEARCH.md recommendation: show ALL ingredients on every step since the data model has no per-step ingredient assignments.

**Web layout (sidebar + main):**
- Use `useBreakpoint()`. `const isWeb = breakpoint === 'web';`
- flexDirection: 'row' when web.
- **Left sidebar (200px width):**
  - borderRightWidth: 1, borderRightColor: borderDefault
  - List all steps as clickable items:
    - Each: Pressable, padding 16
    - Active step: bgCard background
    - Text: "Step {i + 1}" (fontSizeBase, fontFamilyBody)
    - Active step text: textPrimary + fontFamilyBodyMedium. Inactive: textSecondary.
    - onPress: `setCurrentStep(i)`
- **Main content area (flex: 1):**
  - Same as mobile content but with more generous padding (40px)
  - Text alignment: left instead of center on web

**Bottom Navigation:**
- flexDirection: 'row', justifyContent: 'space-between', padding: 16
- borderTopWidth: 1, borderTopColor: borderDefault
- **Previous button:** "Previous" text with ChevronLeft icon. Disabled (opacity 0.3) when currentStep === 0. onPress: `setCurrentStep(s => s - 1)`.
- **Next button:** "Next" text with ChevronRight icon. When on last step, show "Done" instead. onPress:
  - If not last step: `setCurrentStep(s => s + 1)`
  - If last step: `router.back()` (exit cooking mode)
- Both buttons: Pressable with flexDirection 'row', alignItems 'center', gap 8. Text: fontSizeBase, fontFamilyBody, accentBlue.

**Icons:** Import X, ChevronLeft, ChevronRight from lucide-react-native.

**No nav chrome:** This screen should NOT show the MobileTabBar or WebSidebar. Since it's rendered within the (tabs) route group, check whether the tabs layout hides nav chrome for nested routes. If not, the focused experience should still work since the route is deeply nested under [id]/cook.tsx -- the tab bar may not show for non-tab routes.

**Anti-patterns to avoid:**
- Do NOT use Modal or position:'fixed' -- this is a dedicated route, not an overlay
- Do NOT use Dimensions.get('window') for progress bar -- use percentage width
- Do NOT use StyleSheet.create for breakpoint-dependent values
- Do NOT use hardcoded hex colors
