<objective>
Fix DraftEditor save failure: updateDraftRecipe receives job ID instead of draft primary key

Purpose: All three UAT failures (tests 3, 4, 5) share a single root cause -- the `saveChanges` callback in DraftEditor.tsx passes the `draftId` prop (which is a scan job ID from the route parameter) to `scanDraftService.updateDraftRecipe`, but that service method calls `getDraft(draftId, userId)` which queries by the draft's primary key (`scan_drafts.id`). Since no draft has `id` equal to the job ID, `getDraft` returns null and throws "Draft not found", surfacing as "Failed to update draft recipe" to the user.

Output: A working DraftEditor that saves edits using the draft's actual primary key (`draft.id`) from the loaded draft object.
</objective>
