<objective>
Fix the retry failure (UAT test 3) caused by broken `profiles!inner` joins and invalid status values. RetryRecoveryService and JobStatusService join scan_jobs to profiles requesting subscription_tier, but that column lives on scan_jobs (added by the enhanced_job_status migration). Additionally, retryJob sets status='retrying' but scan_jobs CHECK constraint only allows queued|processing|completed|failed.

Purpose: Retry is a critical recovery path for failed scans. Without it, users with failed scans have no recourse except re-uploading photos.

Output: Working retry flow, correct subscription_tier reads, and scan_jobs CHECK constraint that accepts 'retrying' and 'cancelled' statuses.
</objective>

    -- Fix scan_jobs status CHECK constraint to include retrying and cancelled
    -- These statuses are used by retry-recovery-service and job-status-service
    -- but were only added to job_status_history, not scan_jobs itself.
    -- Date: 2026-03-02

    -- Drop existing constraint
    alter table public.scan_jobs drop constraint if exists scan_jobs_status_check;

    -- Add updated constraint with all valid statuses
    alter table public.scan_jobs
      add constraint scan_jobs_status_check
      check (status in ('queued', 'processing', 'completed', 'failed', 'retrying', 'cancelled'));

    commit;
