# Phase 3 Plan 1: SCAN-01 - Photo Upload & Job System

## Objective
Implement photo upload workflow with scan job creation, queue management, and real-time status tracking. Users can upload recipe photos to initiate AI scanning and monitor progress.

## Context Files
- `.planning/phases/03-scan-to-draft-photo-to-structured/03-CONTEXT.md`

## Tasks

### Task 1: Database Schema for Scan System
- **type:** auto
- **behavior:** 
  - Create `scan_jobs` table with columns: id, user_id, photo_url, status, created_at, updated_at, error_message
  - Create `scan_drafts` table for future task (empty placeholder)
  - Add RLS policies: users can only access their own jobs
  - Create indexes for performance on user_id and status
- **done:** Tables created with proper constraints and policies

### Task 2: Photo Upload API Endpoint
- **type:** auto
- **behavior:**
  - Extend Phase 2 photo upload infrastructure
  - Add client-side image compression and quality estimation
  - Create Supabase Edge Function for scan job creation
  - Store compressed photo in Supabase Storage
  - Return job ID to client for status tracking
- **done:** Photo upload creates scan job and returns tracking ID

### Task 3: Job Queue System
- **type:** auto
- **behavior:**
  - Implement queue table for job processing
  - Add job status transitions: queued → processing → completed/failed
  - Create queue worker system using Supabase Edge Functions
  - Add retry mechanism with exponential backoff (max 3 attempts)
  - Implement rate limiting: 3 concurrent jobs per user
- **done:** Queue system processes jobs reliably with retries

### Task 4: Real-time Status Tracking
- **type:** auto
- **behavior:**
  - Add realtime subscription to scan_jobs table
  - Create job status UI component showing progress
  - Display estimated time remaining for processing jobs
  - Show error messages for failed scans with retry options
  - Add job cancellation capability for queued jobs
- **done:** Users see live scan progress and can manage jobs

## Verification
1. Photo upload compression works and reduces file size appropriately
2. Scan job creation returns valid tracking ID
3. Queue system processes jobs without corruption
4. Real-time status updates reflect actual job state changes
5. Rate limiting prevents more than 3 concurrent jobs per user
6. Failed jobs show actionable error messages

## Success Criteria
1. User can upload a photo to start a scan job and see progress/status
2. Photo compression works without significant quality loss
3. Job queue processes items reliably with retry logic
4. Real-time status updates work across browser sessions
5. Error handling prevents job corruption and provides retry paths

## Output Specification
- Database migrations for scan system tables
- Edge Functions for job creation and queue processing
- React components for photo upload and status tracking
- Real-time subscription implementation
- Rate limiting middleware
