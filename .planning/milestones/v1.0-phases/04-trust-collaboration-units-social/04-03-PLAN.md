**types.ts:**
```typescript
export type Comment = {
  id: string;
  recipe_id: string;
  user_id: string;
  parent_comment_id: string | null;
  content: string;
  is_edited: boolean;
  created_at: string;
  updated_at: string;
  depth: number;
  path: string;
  // Joined from profiles
  author_display_name?: string;
  author_email?: string;
};

export type CreateCommentInput = {
  recipe_id: string;
  content: string;
  parent_comment_id?: string;
};

export type UpdateCommentInput = {
  content: string;
};
```

**api.ts:**
- `getRecipeComments(recipeId: string): Promise<Comment[]>` — Calls `supabase.rpc('get_recipe_comments', { p_recipe_id: recipeId })`. The RPC returns threaded results. After fetching, do a secondary query to get author display_name/email from profiles for all unique user_ids in the result, then merge into the comments array. This avoids needing to modify the SQL function.
- `createComment(input: CreateCommentInput): Promise<Comment>` — Inserts into recipe_comments via `supabase.from('recipe_comments').insert(...)`. Sets user_id from current auth. Returns the created comment (use `.select().single()`).
- `updateComment(commentId: string, input: UpdateCommentInput): Promise<Comment>` — Updates content and sets is_edited to true: `supabase.from('recipe_comments').update({ content: input.content, is_edited: true }).eq('id', commentId)`. RLS enforces only own comments can be updated.
- `deleteComment(commentId: string): Promise<void>` — Deletes via `supabase.from('recipe_comments').delete().eq('id', commentId)`. RLS enforces authorization (own comment, recipe owner, or family admin).

Follow the same pattern as `src/features/recipes/api.ts` — import supabase from `@/lib/supabase`, throw on error, return typed data.

**CommentInput.tsx:**
- Props: `{ recipeId: string, parentCommentId?: string, initialContent?: string, isEditing?: boolean, onSubmit: () => void, onCancel?: () => void }`
- State: content text, isSubmitting boolean
- Renders a TextInput (multiline, placeholder "Add a comment...") and Submit/Cancel buttons
- On submit: calls createComment (or updateComment if isEditing) then calls onSubmit callback
- If isEditing, pre-populate with initialContent
- Disable submit button while isSubmitting or content is empty
- Style: white background, rounded border, consistent with app's existing form patterns

**CommentThread.tsx:**
- Props: `{ recipeId: string, recipeOwnerId: string, recipeFamilyId?: string | null }`
- State: comments array, isLoading, showReplyFormFor (comment id or null), editingCommentId (string or null)
- On mount (useEffect), call getRecipeComments(recipeId) to load threaded comments
- Group comments by parent_comment_id (null = top-level, else keyed by parent id)
- Render top-level comments, each with nested replies
- For each comment item:
  - Show author (display_name or email fallback), timestamp (relative: "2h ago", "3d ago"), content
  - If is_edited, show "(edited)" in gray text after content (per locked decision)
  - Show "Reply" button if depth < 3 (UI flattens after depth 3 per research)
  - Show "Edit" button if comment.user_id === session.user.id
  - Show "Delete" button if: own comment, OR session.user.id === recipeOwnerId, OR user is family admin of recipeFamilyId
  - For family admin check: call is_family_admin or check family_memberships. Simplest approach: pass a `canModerate` boolean prop computed in the parent, or fetch the user's role for the recipe's family_id once
  - Indent nested comments with marginLeft: depth * 16 (max depth 3 visually)
- At bottom of comment list, render CommentInput for new top-level comments
- When reply form is shown for a comment, render CommentInput below that comment with parentCommentId set
- After any create/update/delete, reload comments by calling getRecipeComments again
