**types.ts:**
```typescript
export type RecipeRating = {
  recipe_id: string;
  user_id: string;
  rating: number;  // 0.5 to 5.0 in 0.5 increments
  created_at: string;
  updated_at: string;
};

export type RatingAggregate = {
  average: number | null;  // null if no ratings
  count: number;
};
```

**api.ts:**
- `getUserRating(recipeId: string): Promise<RecipeRating | null>` — Fetches the current user's rating for a recipe. Uses `supabase.from('recipe_ratings').select('*').eq('recipe_id', recipeId).eq('user_id', userId).maybeSingle()`. Get userId from `supabase.auth.getUser()`. Returns null if no rating exists.

- `upsertRating(recipeId: string, rating: number): Promise<RecipeRating>` — Uses `supabase.from('recipe_ratings').upsert({ recipe_id: recipeId, user_id: userId, rating }, { onConflict: 'recipe_id,user_id' }).select().single()`. This handles both create and update in one call since the table has a composite PK. The trigger will auto-update recipes.rating_average and rating_count.

- `deleteRating(recipeId: string): Promise<void>` — Deletes the user's rating: `supabase.from('recipe_ratings').delete().eq('recipe_id', recipeId).eq('user_id', userId)`. Trigger will update aggregates.

- `getRecipeRatingAggregate(recipeId: string): Promise<RatingAggregate>` — Rather than a separate query, read from the denormalized recipes columns: `supabase.from('recipes').select('rating_average, rating_count').eq('id', recipeId).single()`. Return `{ average: data.rating_average, count: data.rating_count }`.

Follow same patterns as existing API files. Import supabase from `@/lib/supabase`, throw on error.

**StarRating.tsx:**

Props:
```typescript
type StarRatingProps = {
  value: number;          // 0-5 in 0.5 increments (0 = no rating selected)
  onChange?: (rating: number) => void;  // undefined = readonly mode
  size?: number;          // star size in points, default 32
  showValue?: boolean;    // show numeric value next to stars, default false
};
```

Implementation:
- Render 5 Pressable star elements in a horizontal row
- Each star has minimum dimensions of 44x44pt (mobile touch target guideline) regardless of visual star size. Use hitSlop if needed to expand touch area.
- Star size prop controls the font size of the star character
- For each star position (1-5):
  - If value >= position: show filled star (use unicode character, golden color #FFD700)
  - If value >= position - 0.5 and value < position: show half-filled star
  - Otherwise: show empty star (use lighter color #D4D4D4)
- Half-star rendering approach: Use two overlapping Text elements — a gray empty star as base, and a clipped golden filled star on top. Alternative simpler approach: use three different characters. Research suggested Unicode characters. Pick whichever renders correctly cross-platform. Test with: filled = '\u2605' (black star), empty = '\u2606' (white star). For half-filled, consider using a View with overflow hidden at 50% width containing a filled star, overlaid on an empty star.
- On press: use `event.nativeEvent.locationX` to determine if user tapped the left half (= X.5 rating) or right half (= X.0 rating) of the star
  - `const halfWidth = size / 2; const isLeftHalf = locationX < halfWidth;`
  - `const newRating = starIndex + (isLeftHalf ? 0.5 : 1);`
  - But note: starIndex should be 0-based for this calculation. If stars are indexed 1-5, then: `newRating = (starIndex - 1) + (isLeftHalf ? 0.5 : 1)`
- If onChange is undefined, stars are readonly (Pressable disabled)
- If showValue is true, show the numeric value and count next to stars: "4.5 (12 ratings)"
