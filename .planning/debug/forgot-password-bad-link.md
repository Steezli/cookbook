test: Check Supabase dashboard > Authentication > URL Configuration > Site URL
expecting: Site URL is set to localhost:3000 or another incorrect value

## Eliminated

- hypothesis: The edge function constructs the URL incorrectly in code
  evidence: |
    `supabase/functions/reset-request/index.ts` does NOT construct any URL itself.
    It passes `redirectTo` through to `supabase.auth.resetPasswordForEmail(email, { redirectTo })`.
    The actual email link is generated by Supabase Auth internally, not by our code.
  timestamp: 2026-03-10

- hypothesis: The `forgot-password.tsx` client passes a bad redirect URL
  evidence: |
    The client passes `Linking.createURL('/(auth)/reset-password')` as `redirect_to`.
    On web this produces something like `http://localhost:8081/(auth)/reset-password` (dev) or
    the deployed URL (prod). On native it produces `berven:///(auth)/reset-password`.
    However, this is the `redirectTo` param -- it tells Supabase where to redirect AFTER
    the token is verified. The base URL in the email link itself (the one users see/click)
    is controlled by Supabase Auth's own `site_url` setting, NOT this parameter.
  timestamp: 2026-03-10

  found: |

    This is passed as `redirect_to` in the request body.
  implication: |
    The `redirectTo` param only controls the post-verification redirect.
    The `localhost:3000` in the email link is the Supabase Auth `site_url`, not this value.

- timestamp: 2026-03-10
  checked: How Supabase Auth password reset emails work
  found: |
    Supabase Auth generates the reset link as:
    `{SITE_URL}/auth/v1/verify?token=...&type=recovery&redirect_to=...`
    or in newer versions:
    `{SUPABASE_URL}/auth/v1/verify?token=...&type=recovery&redirect_to=...`
    The `SITE_URL` is set in the Supabase dashboard under Authentication > URL Configuration.
    If this is `http://localhost:3000`, that is what appears in the email.
  implication: Root cause is a Supabase dashboard configuration issue, not a code issue.

## Resolution

root_cause: |
  The Supabase project's **Site URL** setting (in the Supabase dashboard under
  Authentication > URL Configuration) is set to `http://localhost:3000`.

  Supabase Auth uses this `site_url` as the base for all auth-related email links
  (confirmation, password reset, magic link, etc.). When `resetPasswordForEmail` is
  called, Supabase Auth generates the email with a verification link that starts with
  `{site_url}`, resulting in `http://localhost:3000/...` in the email.

  This is a **dashboard/infrastructure config issue**, not a code bug. No code changes
  are needed.

fix: |
  **Action required in Supabase Dashboard (not in code):**

  1. Go to https://supabase.com/dashboard/project/ugixgcbysrwabwzbsjxr/auth/url-configuration
  2. Set **Site URL** to the production app URL (e.g., `https://your-app-domain.com`)
  3. Add the production URL and any staging URLs to **Redirect URLs** allowlist
  4. Also add the native deep link scheme: `berven://**`
  5. Save changes

  The `supabase/config.toml` `site_url` only affects local development and is fine as-is.

verification: |
